核心技术：PPP协议（点到点协议），支持专线链路适配+身份验证（PAP/CHAP），保障跨地域连接安全。

PPP协议核心配置命令（总部路由器）

// 1. 进入连接专线的物理接口（如Serial 2/0）
BJ-Router(config)# interface serial 2/0
// 2. 配置接口IP（与分部路由器互联网段，如20.0.0.1/30）
BJ-Router(config-if)# ip address 20.0.0.1 255.255.255.252
// 3. 配置接口时钟频率，取640000
BJ-Router(config-if)# clock rate 64000
// 3. 启用PPP封装（替换默认的HDLC，适配专线）
BJ-Router(config-if)# encapsulation ppp
// 4. 配置CHAP身份验证（更安全，替代PAP）
BJ-Router(config-if)# ppp authentication chap
// 5. 配置CHAP认证的用户名和密码（分部需相同）
BJ-Router(config)# username SH-Router password ppp123
// 分部路由器对应配置（仅需修改IP和用户名）
SH-Router(config)# interface serial 3/0
SH-Router(config-if)# ip address 20.0.0.2 255.255.255.252
SH-Router(config-if)# encapsulation ppp
SH-Router(config-if)# ppp authentication chap
SH-Router(config)# username BJ-Router password ppp123

📚 ACL通用配置格式

1. 标准ACL配置格式（控制源IP）

// 全局模式创建标准ACL（编号1-99）
Router(config)# access-list [编号] permit/deny [源IP地址] [反掩码]
// 应用到路由器接口（inbound=入站，outbound=出站）
Router(config)# interface [接口名称]（如fastethernet 0/1）
Router(config-if)# ip access-group [编号] in/out

2. 扩展ACL配置格式（控制源IP+目标IP+端口）

// 全局模式创建扩展ACL（编号100-199）
Router(config)# access-list [编号] permit/deny [协议类型] [源IP] [反掩码] [目标IP] [反掩码] eq [端口号]
// 应用到路由器接口
Router(config)# interface [接口名称]
Router(config-if)# ip access-group [编号] in/out

关键说明：反掩码与子网掩码互补（如/24子网的反掩码为0.0.0.255），eq表示“等于某个端口”（如eq 80对应HTTP服务）。

示例1：标准ACL配置（禁止市场部访问财务网段）

// 1. 创建标准ACL（编号10，属于标准ACL范围1-99）
Router(config)# access-list 10 permit 192.168.10.0 0.0.0.255
Router(config)# access-list 10 permit 192.168.1.0 0.0.0.255
Router(config)# access-list 10 deny 192.168.20.0 0.0.0.255
Router(config)# access-list 10 deny any
// 2. 应用到路由器连接财务网段的接口（假设为fastethernet 6/0，出站方向）
Router(config)# interface fastethernet 6/0
Router(config-if)# ip access-group 10 out

示例2：扩展ACL配置（不允许市场部访问财务服务器）

// 1. 创建扩展ACL（编号100，属于扩展ACL范围100-199）
Router(config)# access-list 100 deny ip any host 192.168.30.10
Router(config)# access-list 100 permit ip any any
// 2. 应用到路由器连接市场网段的接口（假设为fastethernet 7/0，入站方向）
Router(config)# interface fastethernet 7/0
Router(config-if)# ip access-group 100 in
// 3. 验证ACL配置
Router# show access-lists
Router# show ip access-group

问题导入： "公司内部网络使用私有IP地址，无法直接访问互联网，同时需要保护内部网络结构不被外部知晓，如何解决？"

答案："配置网络地址转换（NAT）技术"

🌐 关键概念：NAT技术

网络地址转换（NAT）通过将内部私有IP地址转换为公共IP地址，实现私有网络与互联网的通信，同时隐藏内部网络结构，提升安全性。常见类型包括静态NAT、动态NAT和端口地址转换（PAT）。

NAT配置命令

// 配置内部接口（连接私有网络）
bj-Router(config): interface fastethernet 0/0
bj-Router(config-if): ip address 192.168.1.1 255.255.255.0
bj-Router(config-if): ip nat inside
bj-Router(config-if): no shutdown
// 配置外部接口（连接互联网）
bj-Router(config): interface serial 2/0
bj-Router(config-if): ip address 20.0.1.1 255.255.255.0
bj-Router(config-if): ip nat outside
bj-Router(config-if): no shutdown
// 配置动态NAT地址池
bj-Router(config): ip nat pool public 20.0.1.10 20.0.1.20 netmask 255.255.255.0
// 定义访问控制列表匹配内部网络
bj-Router(config): access-list 1 permit 192.168.1.0 0.0.0.255
// 关联地址池和访问控制列表
bj-Router(config): ip nat inside source list 1 pool public
// 静态NAT配置（一对一映射，适用于内部服务器）
// 格式：ip nat inside source static 内部私有IP 外部公共IP
Router(config): ip nat inside source static 192.168.1.100 20.0.1.8
// 说明：将内部服务器IP(192.168.1.100)固定映射为公共IP(20.0.1.8)

虚拟局域网(VLAN)

随着公司规模扩大，北京总部办公室人员增多，部门划分更细致（研发部、市场部、财务部），所有设备连接在同一台交换机上导致广播风暴和安全隐患。

问题导入： "如何在同一台物理交换机上，将不同部门的设备通信隔离开？"

🔒 关键概念：虚拟局域网(VLAN)

将一个物理局域网在逻辑上划分成多个不同的广播域（子网络）。

VLAN的核心作用

  • 广播控制：限制广播帧只在本VLAN内传播，避免广播风暴
  • 安全隔离：不同VLAN设备默认无法直接通信，保护敏感部门数据
  • 灵活管理：设备可以根据部门需求划分到不同VLAN，不受物理位置限制

VLAN类型

静态VLAN

由管理员手动将交换机接口分配给特定VLAN

优点：安全可靠，易于监控

缺点：设备移动时需要重新配置

动态VLAN

基于MAC地址、IP地址或用户账号自动分配VLAN

优点：设备移动时自动适应

缺点：配置复杂，需要额外服务器支持

VLAN间通信

不同VLAN之间默认无法通信，需要通过路由器或三层交换机实现互通，这一过程称为"VLAN间路由"。

具体配置方法查看下一阶段“网络互联”中的"单臂路由"

内部网关协议(IGP)

用于在同一个自治系统内部(AS)交换路由信息的动态路由协议

🏢 关键概念：自治系统(AS)

网络世界的 “独立行政区”

自治系统（Autonomous System，简称 AS）是互联网中由单一机构（如企业、运营商、高校）管理、遵循统一路由策略的独立网络集合，可以通俗理解为网络世界里的 “独立行政区”—— 有自己的 “管理规则” 和 “对外联络方式”，内部自主管理，外部通过固定 “接口” 与其他 “行政区”（其他 AS）互联互通。

常见IGP协议对比

RIP (路由信息协议)

类型： 距离矢量协议

工作原理： 像"传话游戏"，每个路由器只告诉邻居自己到各网络的距离（跳数）

优点： 配置简单，易于理解

缺点： 最大跳数15跳，收敛速度慢，可能产生路由环路

适用场景： 小型网络，拓扑简单

RIP协议详细介绍

OSPF (开放最短路径优先)

类型： 链路状态协议

工作原理： 像"实时共享的电子地图"，所有路由器有相同的全网拓扑图

优点： 收敛速度快，无跳数限制，支持分层设计

缺点： 配置复杂，资源消耗较大

适用场景： 大型复杂网络

外部网关协议(EGP)

当总部和分部属于不同的AS时，需要使用EGP类协议才能进行互联互通。如左图所示，北京核心区属于AS 100，上海分区属于AS 200，两部门因组织架构或网络管理边界划分为不同AS。每个AS内部通过IGP（黑色链路）实现核心路由互通，AS之间通过边界路由器（BJ-Edge与SH-Edge）建立EGP邻居关系（红色链路），核心目的是安全、可控地实现跨部门（跨AS）的业务路由传递，适配不同部门的独立网络管理需求。

BGP协议是典型的EGP类协议。

BGP协议详细介绍
⚙️ BGP协议核心配置命令格式

广域网PPP协议

📚 关键概念：PPP协议

PPP（Point-to-Point Protocol，点到点协议）是广域网中常用的链路层协议，核心作用：

  • 链路适配：支持专线、拨号等多种广域网链路，替代路由器默认的HDLC（仅支持同品牌设备）；
  • 身份验证：提供PAP（明文验证，简单）和CHAP（加密验证，安全），防止链路被非法设备接入；

PPP与网络互联的逻辑关系

在极客公司场景中，PPP是“网络互联”的链路基础：

  1. 第一步：通过PPP配置专线链路（北京总部Serial 2/0 ↔ 上海分部Serial 2/0），确保物理链路能通；
  2. 第二步：在PPP链路基础上，配置动态路由（如OSPF），实现总部192.168.1.0与分部192.168.2.0的互通；
  3. 简单说：PPP解决“链路能不能通”，路由解决“数据往哪传”。

验证方法：

  • 1. 接口状态验证：执行 show ip interface brief，查看Serial接口状态为“up/up”（表示PPP链路已建立）；
  • 2. 身份验证：执行 show ppp authentication，查看CHAP验证状态为“SUCCEEDED”（表示验证通过）；
  • 3. 连通性验证：总部路由器ping分部路由器互联IP（20.0.0.2），能通则PPP链路正常。

防火墙ACL

📚 核心知识点
  • ACL分类：标准ACL（控制源IP）、扩展ACL（控制源IP+目标IP+端口）
  • 应用方向：inbound（入站，数据进入接口时检测）、outbound（出站，数据离开接口时检测）
  • 匹配顺序：ACL规则自上而下执行，一旦匹配立即生效，后续规则不再执行
什么是ACL？
🚨 关键概念：路由器ACL（访问控制列表）

路由器的"访问规则清单"，通过允许/拒绝特定IP、端口的数据包，控制不同网段间的访问权限，保护内部敏感资源（如财务服务器）。

核心原则：默认拒绝所有，只允许需要的访问（最小权限原则）

编号与ACL类型对应关系：

  • 标准ACL（仅控制源IP）：编号 1-99 或 1300-1999
  • 扩展ACL（控制源IP+目标IP+端口）：编号 100-199 或 2000-2699

配置原则：标准ACL尽量靠近目标设备，扩展ACL尽量靠近源设备（减少无效数据传输）。

2. 需求2：禁止研发部（192.168.10.0/24）访问财务服务器 → 用扩展ACL（控制源IP+目标IP+80）。

注意事项：

  • ACL编号决定类型：1-99/1300-1999是标准ACL（仅源IP），100-199/2000-2699是扩展ACL（源IP+目标IP+端口），不可混淆。

  • 接口方向：inbound是“数据进入接口时验证”，outbound是“数据离开接口时验证”，需根据ACL类型选择（标准ACL靠近目标，扩展ACL靠近源）。

网络地址转换(Network Address Translation,NAT)

📚 核心知识点
  • 解决IPv4地址枯竭问题：多个内部设备共享一个公共IP
  • 隐藏内部网络拓扑：外部仅能看到公共IP，无法获取私有IP段
  • 提升网络安全性：隔绝外部直接访问内部设备，减少攻击面

二、NAT的三种常见类型

  • 静态NAT：私有IP与公共IP一对一固定映射（适用于服务器对外提供服务）
  • 动态NAT：私有IP从公共IP池中随机获取映射（适用于多设备访问互联网）
  • PAT（端口地址转换）：多私有IP共享一个公共IP，通过端口号区分（最常用，如家庭路由器）
NAT协议原理讲解微课视频

二、核心配置组件

  • 内部接口：连接私有网络的接口（需配置ip nat inside）
  • 外部接口：连接互联网的接口（需配置ip nat outside）
  • 地址池：存放可分配的公共IP地址范围（动态NAT/PAT用）
  • 访问控制列表（ACL）：定义哪些内部设备可以使用NAT转换

三、设计思路提示

  • 💡 网段规划：避免与公网IP冲突，建议使用192.168.0.0/16私有网段，每个区域子网掩码255.255.255.0
  • 💡 VLAN配置：交换机之间需配置Trunk链路，允许所有VLAN通过；接入端口配置为Access模式并划分到对应VLAN
  • 💡 PPP配置：参考阶段4，核心路由器Serial接口配置encapsulation ppp和CHAP认证，对接运营商侧IP（20.0.0.2）
  • 💡 ACL配置：扩展ACL（编号100-199）部署在路由器连接客房的子接口（入站方向），精准控制源IP+目标IP
  • 💡 VPN配置：参考阶段6，核心路由器配置ISAKMP策略和预共享密钥，远程设备连接时输入路由器公网IP（20.0.0.1）
